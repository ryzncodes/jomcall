# JomCall — agent handover

The product name is **JomCall**. Use `JomCall` in user-facing text and `jomcall` (or `jomcall_`, `JOMCALL_`) in code identifiers.

It answers Malaysian SMEs' phone calls and WhatsApp messages 24/7 with an AI agent that speaks the caller's language (BM, English, Manglish, Mandarin), answers questions, books appointments, takes messages and transfers to staff. Inbound is the core business; outbound lead follow-up is secondary. Delivered as a hosted self-serve SaaS (MYR billing) with the full code public under FSL-1.1-ALv2 (source-available; each release converts to Apache-2.0 after two years).

A real phone call is billed `voice_second` once, keyed `call:<call id>`, inside `app_private.agent_call` when it ends: `call_end` (hang-up, transfer, worker error) or `maintain` (worker crash). The seconds are the call row's `duration_seconds` from the answer, stored as `billed_seconds`, priced under the price version and plan period in force at the answer. If the worker's answer report is lost (it retries three times in the background), the caller's first turn sets `answered_at`, so a call in which the caller spoke is never free. After a crash the seconds stop at the end of the last turn (`call_turn.completed_at`); unanswered and refused calls are not billed; browser test calls stay free. A failed bill leaves the call `usage_state='pending'` for `maintain` (up to 20 attempts); `npm run billing:admin -- usage-pending` lists owed bills and `usage-retry <id>` retries one past the cap. WhatsApp bills `whatsapp_conversation` once per customer (contact and channel) per 24 hours, however often staff resolve and reopen the chat (owner decision D): the window (`app.whatsapp_usage_window`) starts when the provider's `sent` is recorded for an agent message while none is open, keyed `wa:<channel id>:<contact id>:<start in Unix seconds>`, priced at its start; notices, staff replies and unanswered chats are not billed; a Meta `failed` after `sent` is not reversed. Admission (`app_private.channel_admission`, never raises) runs only after every other refusal and only for a customer with no open window; it starts or retries the plan period (this may debit the monthly fee at the first admitted call or chat of a period; since 2026-11-16, on branch `feat/plan-picker`, the engine also visits due organizations hourly) at the database clock. Refusals: `NO_PHONE_ENTITLEMENT` / `NO_WHATSAPP_ENTITLEMENT`, then `WALLET_UNFUNDED` / `WALLET_EXHAUSTED`; but a phone call is admitted while a charged period has unused included minutes, whatever the wallet (owner decision B; WhatsApp unchanged, no plan includes free conversations). A refused call ends silently (room deleted, refused row); a refused WhatsApp turn is skipped, the conversation flagged (`needs_attention`) and nothing sent; the caller and customer are told nothing. If the billing check itself fails, the call or turn is answered anyway and `BILLING_CHECK_FAILED` is stored on `app.call.billing_check` or `app.conversation_turn.billing_check` and logged as a database warning without personal data (owner decision A); it is still metered and `usage-pending` lists it. On the four plan or wallet refusals the organization's owners get one email per reason per Kuala Lumpur day, English and BM, linking `/app/billing`, with no customer number or text (owner decision C): `channel_admission` calls `app_private.queue_billing_notice` (owned by `jomcall_jobs`, executable only by `jomcall_agent_jobs`), which inserts an `app.billing_notice` row and one outbox row of kind `billing.refusal_notice`; the engine sends it (`engine/src/billing-notice.ts`), never the agent process. Grace is served. A call in progress, or a chat inside an open window, is never cut off; a chat that outlives its window is checked again and can go unanswered (awaiting the owner's decision). The agent login role lost direct access to `record_usage`, `wallet_state` and `plan_entitlements`; the web role reads `app.call` column by column without the billing columns, so a migration adding a column to it must grant it to `jomcall_app`. **Every existing organization without a plan is refused on the phone and gets no WhatsApp agent replies after this migration** (and its owners get the daily email) until it has a plan: an operator runs `npm run billing:admin -- plan <org> <starter|growth|payg> "<operator>"` (local database only; on staging the owner runs the equivalent SQL, see the pull request), or, since the plan picker (2026-11-16, branch `feat/plan-picker`, not merged), its owner picks a plan on `/app/billing`; browser and typed tests are unaffected. ## Rules

- **Original work only.** Write everything from scratch. Do not copy code, endpoint paths, schemas, names, prompts, copy text or assets from other products.
- **No secrets in git.** Keys go in local `.env` files only (gitignored). Never print or commit keys or tokens.
- **No personal data in git.** No real call audio, transcripts or customer data; use clearly fake sample data (fake names, fake numbers).
- **Malaysia first.** UI in BM and English; amounts in MYR (store as integer sen); times in `Asia/Kuala_Lumpur`; phone numbers in E.164; mobile-first, because owners check calls on their phones.
- **Compliance is visible in the UI:** AI and recording disclosure setting, consent records, do-not-contact switch, PDPA export and delete.
- **License:** FSL-1.1-ALv2 (see `LICENSE.md`). Only add dependencies whose licenses allow use in commercial, source-available software (MIT, Apache-2.0, BSD, ISC and similar). Avoid GPL/AGPL dependencies. One exception, accepted by the owner on 2026-11-13: the voice service may use LiveKit's turn-detector model under the proprietary LiveKit Model License. It is optional, is not redistributed here, and the service must work without it. Open, awaiting the owner's decision (found 2026-11-14): the Python voice worker's dependency `av` (BSD-3-Clause, required by livekit-agents) ships a wheel that bundles FFmpeg built with libx264 and libx265 (GPL-2.0-or-later); JomCall does not redistribute these binaries, but they are loaded at runtime.
- Commits: small, Conventional Commits style. Work on a feature branch, not `main`.
